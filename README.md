# ReelBot

ReelBot — Telegram-бот для подготовки коротких роликов и контролируемой публикации в Instagram Reels. Он сохраняет исходную длительность видео, распознаёт русскую или казахскую речь, добавляет субтитры, создаёт обложку и двуязычное описание. Публикация начинается только после явного нажатия кнопки **«Одобрить и опубликовать»**.

Бот помогает качественно упаковать контент, но не может гарантировать охваты или «вирусность»: итог зависит от темы, самого ролика, аудитории и алгоритмов Instagram.

## Как это работает

1. Разрешённый пользователь отправляет боту видео размером до 20 МБ либо общедоступную ссылку Google Drive.
2. Бот извлекает звук и распознаёт речь без перевода на другой язык.
3. Субтитры накладываются на весь ролик. Видео не обрезается; для добавления текста оно технически перекодируется.
4. Бот создаёт вертикальную обложку с коротким хуком и описание: сначала на казахском, ниже на русском, затем релевантные хештеги.
5. В Telegram приходят обложка, готовое видео и текст. Можно отклонить результат или одобрить публикацию.
6. После одобрения бот публикует Reel через официальный Instagram Graph API и присылает ссылку.

Если внешний сервис временно недоступен, команда `/retry ID` повторяет обработку или публикацию без повторной загрузки. Команда `/preview ID` заново присылает уже готовый предпросмотр.

Состояние заданий хранится в SQLite, поэтому перезапуск процесса не должен терять очередь. Каталог `data/` нужно размещать на постоянном диске.

## Что потребуется

- Python 3.11 и `ffmpeg` с поддержкой libass;
- шрифт DejaVu Sans с кириллицей и казахскими буквами;
- Telegram-бот, созданный через `@BotFather`;
- ключ OpenAI для распознавания речи и подготовки текста;
- профессиональный Instagram-аккаунт типа **Creator** или **Business**, связанный со страницей Facebook;
- долгоживущий Meta access token с разрешениями, необходимыми для чтения аккаунта и публикации контента (обычно `instagram_basic`, `instagram_content_publish`, `pages_show_list` и `pages_read_engagement`);
- публичный HTTPS-адрес сервиса. Instagram должен скачать готовое видео и обложку по этому адресу во время публикации.

Личный Instagram-аккаунт официальный API автоматически публиковать не позволяет. Неофициальная автоматизация входа намеренно не используется: она ненадёжна и может привести к блокировке аккаунта.

## Локальный запуск

В Debian/Ubuntu установите системные зависимости:

```bash
sudo apt-get update
sudo apt-get install -y ffmpeg fonts-dejavu-core
```

Создайте окружение и установите закреплённые версии Python-зависимостей:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
cp .env.example .env
```

Заполните `.env`, не добавляя его в Git, затем запустите один экземпляр приложения:

```bash
python -m reelbot
```

Проверка состояния HTTP-сервиса доступна по адресу `http://127.0.0.1:8000/healthz`. Для Telegram используется long polling, поэтому отдельный публичный webhook не требуется. Несколько одновременно запущенных экземпляров с одной SQLite-базой и одним Telegram-токеном не поддерживаются.

## Запуск в Docker

```bash
docker build -t reelbot .
docker volume create reelbot-data
docker run --rm \
  --env-file .env \
  -p 8000:8000 \
  -v reelbot-data:/app/data \
  reelbot
```

Контейнер запускается от непривилегированного пользователя. Для production каталог `/app/data` должен быть постоянным, а порт 8000 — доступен через HTTPS с адресом из `PUBLIC_BASE_URL`.
Если вместо именованного тома используется bind mount, каталог на хосте должен быть доступен на запись UID/GID `10001`.

## Постоянный запуск в Railway

В репозитории есть `railway.toml`: Railway собирает корневой `Dockerfile`, проверяет `/healthz` и перезапускает процесс после сбоя. Для надёжной работы настройте один экземпляр сервиса без sleep/scale-to-zero и подключите Volume с точкой монтирования `/app/data`.

Минимальные переменные первого этапа:

```text
TELEGRAM_BOT_TOKEN=...
TELEGRAM_ADMIN_IDS=...
REELBOT_OPENAI_API_KEY=...
DATA_DIR=/app/data
DATABASE_PATH=/app/data/reelbot.sqlite3
MEDIA_ROOT=/app/data/media
HOST=0.0.0.0
```

`PORT` вручную не задавайте: Railway передаёт его автоматически. После **Generate Domain** задайте `PUBLIC_BASE_URL=https://${{RAILWAY_PUBLIC_DOMAIN}}`. Для Instagram позже добавьте `META_ACCESS_TOKEN` и `INSTAGRAM_USER_ID`. Используйте ровно одну replica: Telegram long polling и SQLite не рассчитаны на параллельный запуск нескольких экземпляров.

## Настройки

Все параметры перечислены в `.env.example`. Обязательные для полного цикла:

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | секретный токен Telegram-бота |
| `TELEGRAM_ADMIN_IDS` | числовые Telegram ID пользователей через запятую |
| `REELBOT_OPENAI_API_KEY` | ключ распознавания речи и генерации текста |
| `META_ACCESS_TOKEN` | долгоживущий токен Meta Graph API |
| `INSTAGRAM_USER_ID` | ID профессионального Instagram-аккаунта |
| `PUBLIC_BASE_URL` | публичный HTTPS-адрес этого сервиса без завершающего `/` |
| `DATABASE_PATH` | путь к SQLite-базе на постоянном диске |
| `MEDIA_ROOT` | каталог исходных и готовых медиафайлов |
| `MAX_DRIVE_DOWNLOAD_MB` | максимальный размер файла Google Drive, по умолчанию 500 МБ |
| `DRIVE_DOWNLOAD_TIMEOUT_SECONDS` | лимит времени загрузки из Google Drive |
| `MEDIA_COMMAND_TIMEOUT_SECONDS` | лимит времени одной операции ffmpeg |
| `PUBLIC_MEDIA_TTL_HOURS` | срок действия публичной ссылки на медиа, по умолчанию 72 часа |
| `MEDIA_RETENTION_DAYS` | срок хранения файлов завершённых заданий, по умолчанию 30 дней |

Модели и версия Meta API настраиваются отдельно, чтобы их можно было обновить без изменения кода.

## Загрузка больших файлов

Облачный Telegram Bot API позволяет боту скачать файл размером примерно до 20 МБ. Для более тяжёлых исходников отправьте боту ссылку Google Drive и включите доступ **«Все, у кого есть ссылка — читатель»**. Ссылка должна вести на один видеофайл, а не на папку. По умолчанию лимит Drive-файла — 500 МБ. Не публикуйте ссылку за пределами доверенного чата.

Если в будущем будет развёрнут локальный Telegram Bot API server, лимит можно увеличить, но это потребует отдельной инфраструктуры и Telegram API credentials.

## Проверки

```bash
pytest
ruff check src tests
```

Тесты не должны обращаться к реальным Telegram, OpenAI или Meta API. Полная проверка публикации проводится отдельно на тестовом профессиональном Instagram-аккаунте.

## Безопасность и приватность

- Доступ к командам ограничивается списком `TELEGRAM_ADMIN_IDS`.
- Токены хранятся только в переменных среды; `.env` исключён из Git и Docker context.
- Медиафайлы и база исключены из Git. Публичные ссылки на готовые файлы содержат длинный неугадываемый токен доступа и по умолчанию истекают через 72 часа.
- На внешнем HTTPS reverse proxy отключите запись полных путей `/media/...` в access-логи: путь содержит временный токен доступа.
- Исходники, расшифровки и готовые ролики остаются на вашем диске, кроме передачи аудио сервису распознавания и временной загрузки видео Instagram при одобренной публикации.
- Ссылки истекают отдельно; файлы опубликованных, отклонённых и неуспешных заданий автоматически удаляются через `MEDIA_RETENTION_DAYS`, а история SQLite сохраняется. Настройте резервное копирование SQLite в production.
- Бот никогда не публикует ролик автоматически сразу после обработки: требуется отдельное подтверждение пользователя.
